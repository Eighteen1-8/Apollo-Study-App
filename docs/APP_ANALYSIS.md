# Apollo Study: code health analysis

Written 2026-11-03 against the working tree (Electron 33 / React 18 / Vite 5 front end, FastAPI + SQLite sidecar).
Items marked *Fixed* have since been done (the original note is kept after each); the rest are notes only. Each item says where it lives, why it matters, and a
suggested direction. Severity: **High** (data loss, security, or likely breakage soon), **Medium** (real cost or
fragility), **Low** (tidiness, polish).

---

## 1. Security and privacy

| # | Severity | Finding |
|---|---|---|
| 1.1 | ~~High~~ **Fixed 2026-11-03** | **The backend had no authentication, and its CORS allows `Origin: null`.** *Fixed:* every request now needs a per-launch token (`api.require_token`). Electron generates it, passes it to the sidecar by environment variable and to the renderer through the preload. Media URLs carry it as `?token=`. `file://` was dropped from CORS; `null` stays because the packaged app's page sends it, and the token is what keeps other pages out. *Original note:* `api.py` allows `http://localhost:*`, `file://*` and `null`. Any web page can send `Origin: null` from a sandboxed iframe. In dev the port is fixed (47615), and in production it can be found by scanning a few ports. Several endpoints take filesystem paths from the request: `POST /documents` (reads any file into the library, then `/documents/{id}/file` serves it back), `POST /export` and `/documents/{id}/export` (write anywhere), and `/import` and the chat attachments (read anywhere). Together these let a malicious site in the user's normal browser read and write local files while the app runs. **Direction:** have Electron generate a random token per launch, pass it to the sidecar (argument or env) and to the preload, require it as a header on every request, and drop `null` and `file://` from the CORS regex. |
| 1.2 | ~~Medium~~ **Fixed 2026-11-03** | **Path-taking endpoints trusted the caller completely.** *Fixed:* `grants.py`. Electron's main process signs each path the student picks in a dialog or drops in (HMAC with a per-launch key the page never sees). The renderer sends those grants with the request, and the backend refuses to read or write any other path outside its data folder. Node and Python normalise paths the same way (only A–Z are lowercased). *Original note:* Even with a token, the renderer can make the backend read and write any path, so an XSS in rendered LLM output (Markdown, notes HTML, inline SVG diagrams) becomes file access. DOMPurify and `notehtml.clean` are the only barrier. **Direction:** have Electron's main process own the file dialogs and hand out short-lived "grants" (path → token) that the backend checks, or at least restrict writes to paths the user just picked in a dialog. |
| 1.3 | ~~Medium~~ **Fixed 2026-11-03** | **Inline `<svg class="diagram">` from the model is allowed in notes.** *Fixed:* a strict DOMPurify profile in `Markdown.tsx` (no foreignObject, forms, frames or SVG animation; links only to `#`; images only from the backend's assets or `data:`); `notehtml.scrub` strips script-like elements, `on*` handlers and `javascript:` URLs when notes are stored; the built page's CSP has no inline scripts and blocks objects, frames, forms and `<base>`. *Original note:* SVG is a classic XSS route (`<foreignObject>`, `<use href>`, event attributes). Check that the DOMPurify config used for notes has the SVG profile and blocks `foreignObject` and external `href`s. |
| 1.4 | ~~Low~~ **Fixed 2026-11-03** | `sandbox: false` in `BrowserWindow.webPreferences`. *Fixed:* the renderer is sandboxed; the preload gets the backend URL and token over IPC instead of the command line. Checked in a real Electron window: the page has no `require` or `process`. *Original note:* Context isolation is on and the preload API is small, which limits the damage, but a sandboxed renderer is the Electron default for a reason. The preload uses only `ipcRenderer`, `contextBridge` and `webUtils`, which are all available sandboxed, so this can probably be turned on. |
| 1.5 | ~~Low~~ **Fixed 2026-11-03** | API keys sat in plain text in the SQLite `settings` table. *Fixed:* `secret_store.py` encrypts them with Windows DPAPI (bound to the Windows user) when stored, and existing keys are encrypted on the next start. A database copied to another account or PC shows the keys as not set. The root `.env` that seeds them is the user's own file and is left alone. *Original note:* That's acceptable for a local app, but Electron's `safeStorage` (DPAPI on Windows) would keep them off disk in the clear. |
| 1.6 | ~~Low~~ **Fixed 2026-11-03** | Study packs are untrusted input. *Fixed:* their text goes through the 1.3 sanitising, and the imported `render_map` is checked to be a section → [page, y] map. *Original note:* The import validates the manifest, never writes to member paths, checks file hashes and loads vectors without pickle. Text fields still end up rendered as Markdown/HTML, so they rely on the same sanitising as 1.2/1.3. |

## 2. Data integrity and durability

| # | Severity | Finding |
|---|---|---|
| 2.1 | ~~High~~ **Fixed 2026-11-03** | **There were no backups.** *Fixed:* `db.backup` copies the database with SQLite's backup API daily, before migrations, before a restore, and on demand (Settings → Maintenance → Backups, which also restores at the next start). Retention per kind is in `db.KEEP`. The original files and renders aren't copied. *Original note:* Everything (the library, generated content, attempts, annotations) lives in one `study.db` plus loose files. A bad migration, a disk problem or a buggy maintenance cleanup can't be undone. **Direction:** before applying migrations on startup, and daily, copy the database with SQLite's online backup API (`sqlite3.Connection.backup`) and keep the last N copies. Study packs now cover the library, but not artifacts or progress. |
| 2.2 | ~~High~~ **Fixed 2026-11-03** | **Migrations swallowed every error.** *Fixed:* the schema version is in `PRAGMA user_version`. The old statements (`LEGACY_MIGRATIONS`) tolerate only "duplicate column name", and new ones are numbered and transactional. A failure stops start-up with a message, and Electron now shows the backend's start-up error instead of timing out after 30 s. Data from a newer app version is refused. *Original note:* `db.init()` runs each `MIGRATIONS` statement and ignores *any* `OperationalError`, so a typo or a statement that fails for a real reason looks the same as "already applied". There's no schema version, so nothing records what has run. **Direction:** add a `schema_version` (`PRAGMA user_version`), apply numbered migrations once, and only tolerate "duplicate column" for the legacy `ALTER`s. |
| 2.3 | ~~Medium~~ **Fixed 2026-11-03** | **A restart re-ingested from scratch.** *Fixed:* an ingest stopped while embedding finishes only the embeddings (nothing parsed again), and any ingest interrupted by a restart keeps its finished vision notes. *Original note:* Running jobs go back to `queued` on startup, and `pipeline.ingest` begins with `clear_document`. A crash during a 900-page textbook's embedding loses all its chunks and starts parsing again. Vision is kept only when `KEEP_VISION` is set. **Direction:** resume ingest jobs with `keep_vision=True`, and skip re-parsing when units already exist and the parser version matches. Embedding only fills missing vectors anyway. |
| 2.4 | ~~Medium~~ **Fixed 2026-11-03** | **`PARSER_VERSION` had no effect.** *Fixed:* Maintenance → Search index lists files read by an older parser, with **Read again** (`/maintenance/reparse`, vision notes kept for unchanged pages). *Original note:* It's stored per document, but nothing compares it, so parser improvements (e.g. version 2's SmartArt text) never reach older files unless they are re-ingested by hand. Maintenance could list "parsed with an older parser" the same way it lists stale embeddings. |
| 2.5 | ~~Medium~~ **Fixed 2026-11-03** | **One SQLite connection guarded by one global lock.** *Fixed:* each thread reads through its own read-only connection (WAL), so reads never wait for a write; writes and `tx()` stay on one writer connection, and a thread reads its own uncommitted changes inside `tx()`. *Original note:* Every request and every job worker queues on `db._lock`. Long transactions (import, relink, VACUUM, big ingests) block the UI's polling. WAL is on, so per-thread connections would allow concurrent readers. |
| 2.6 | ~~Medium~~ **Fixed 2026-11-03** | **Deleting a file left dangling duplicate links.** *Fixed:* `delete_document` hands the deleted file's vision notes to the pages that duplicated it, then relinks those files (only genuinely new chunks are embedded). Deleting a topic goes newest first, and deleting a subject skips relinking. Which file owns a shared page still follows upload order, by design. *Original note:* `scope_doc_ids` uses `id <= doc.id`, so which file "owns" a shared page depends on upload order, and deleting the owner leaves duplicates pointing at a unit that no longer exists (`duplicate_of` has no foreign key). Deleting a file doesn't relink the others the way a move now does (`pipeline.relink`). **Direction:** call `relink` on the old dependents in `delete_document`, as `move_document` now does. |
| 2.7 | ~~Low~~ **Fixed 2026-11-03** | `practice_exams` and `snapshots` grew forever. *Fixed:* a practice exam is stored once per subject and file, and its parse output goes to a temp folder. Maintenance → Clean up also removes figures and chat images nothing references (chat ones after 7 days), figure-cache and screenshot rows pointing at missing files, older practice-exam copies, and old `practice_*` folders. *Original note:* `figure_cache` has no eviction. Maintenance doesn't show any of them. |

## 3. Likely to break with future upgrades

| # | Severity | Finding |
|---|---|---|
| 3.1 | **High** | **Behaviour specific to the model server is hard-coded.** `reasoning_effort ∈ low|medium|xhigh`, `chat_template_kwargs.enable_thinking`, the rejection of `json_schema`, and the `<think>` handling all match today's ninfer chat template. A new Qwen release or ninfer version that changes the template will break vision, chat and generation at once. **Direction:** move these into a "server profile" setting with a test (Settings → Test connections already exists) that checks each feature works, rather than assuming it. |
| 3.2 | **High** | **The OpenRouter defaults are free models by ID** (`google/gemma-4-26b-a4b-it:free`, `nvidia/nemotron-3.5-embed-1b:free`). Free models disappear without notice. A fresh install that switches to OpenRouter will then fail with a 404. Fetch the list from `/models` and let the user pick, or fail with a clear message. |
| 3.3 | Medium | **Office XML internals.** `omml.py`, `parsers.graphic_text` (SmartArt and chart XPath) and the skipping of `mc:Fallback` reach into python-pptx/python-docx private XML. New Office versions or new python-pptx releases can change these quietly, so text simply goes missing. There are no tests over the real sample files (`spike/samples`). **Direction:** a small golden test that parses 3–4 representative files and compares unit counts, equation counts and key strings. |
| 3.4 | Medium | **`office_export.ps1` drives Microsoft Office over COM** with `-ExecutionPolicy Bypass`. Office updates, missing Office, or Group Policy can break it, and the only signal is the viewer's fallback layout. The 300-second timeout per file is long. Surface the failure reason in Maintenance. |
| 3.5 | Medium | **The front-end dependencies use caret ranges with known breaking majors ahead.** `pdfjs-dist ^4` (v5 changes the worker/ESM setup and the text layer API used in `SourceView`/`annotate`), `react ^18` (19 changes ref and StrictMode behaviour the code relies on), `electron ^33` (now out of support; each major changes Chromium), and `vite ^5`. `package-lock.json` protects today's install, but `npm update` doesn't. |
| 3.6 | Medium | **Python is pinned to `>=3.12,<3.13` with open-ended lower bounds** on everything else (`pymupdf>=1.24`, `numpy>=2.0`, `fastapi>=0.115`). PyMuPDF changes behaviour between minors (text extraction flags, `get_images`). `uv.lock` protects today's build, but a `uv lock --upgrade` can change parsing output silently. Add upper bounds on PyMuPDF and python-pptx. |
| 3.7 | Medium | **Starlette's TestClient warns that `httpx` support is deprecated** (seen in every test run). The tests will break on a future Starlette release. |
| 3.8 | Low | `--parent-pid` watching uses `ctypes.windll`, so the sidecar is Windows-only. That's intended, but nothing guards it besides `os.name == "nt"`. |

## 4. Architecture and maintainability

| # | Severity | Finding |
|---|---|---|
| 4.1 | ~~Medium~~ **Fixed 2026-11-03** | **Very large modules mixed several concerns.** *Fixed:* moved verbatim along their seams. `chat_api.py` 763 → 518 lines, with prompt building in `chat_prompt.py` and chat files in `chat_files.py`. `SourceView.tsx` 857 → 561, with page layouts in `views/source/layouts.tsx` and selection helpers in `source/selection.ts`. `annotate.tsx` 591 → 397, with geometry in `annotate-geometry.ts` and the rail in `AnnotationRail.tsx`. `ArtifactViewer.tsx` 538 → 71, with `views/artifacts/{Flashcards,Quiz,Exam,Sections}.tsx`. *Original note:* `SourceView.tsx` (~860 lines: viewer, toolbar, outline, minimap, snapshot), `chat_api.py` (~760: routes, prompt building, attachments, tools, SSE), `annotate.tsx` (~590), `ArtifactViewer.tsx` (~540). These are hard to change safely and are where regressions cluster. Split along the seams that already exist (prompt building versus HTTP in `chat_api`; toolbar, page and minimap in `SourceView`). |
| 4.2 | ~~Medium~~ **Fixed 2026-11-03** | **Five stacked CSS layers.** *Fixed (safely):* they are now `src/styles/1-base … 5-features.css`, named by purpose and loaded in the same order. 142 declarations that a later rule with the same selector always overrode, and 121 rules for classes used nowhere, were removed (1,901 → ~1,750 lines). The old CSS tooltips and their `!important` override are gone. Computed styles of every element on five screens were identical before and after. A full regrouping by component is still open, because it changes the cascade. *Original note:* (`styles.css` → v2 → v3 → v4 → v5), each re-styling the same selectors. Which rule wins depends on file order and specificity, and several `!important`s exist to settle fights. A change to `.side` or `.btn` has to be checked in four files. **Direction:** merge the layers into component-scoped files (or CSS modules) once the visual design settles, keeping the tokens in one place. |
| 4.3 | ~~Medium~~ **Fixed 2026-11-03** | **Polling everywhere.** *Fixed:* `events.py` checks a cheap signature per topic once a second, and `GET /events` streams what changed. `usePoll(fn, ms, deps, topics)` reloads only on a change (at most once per `ms`), with a 30 s fallback. The chat's progress cards, the viewer's busy check and the knowledge map listen too. *Original note:* About 11 `usePoll` loops (jobs 1.5 s, file lists 2.5 s, library 3 s, documents 4 s, and more) each hit SQLite through the global lock (2.5). With a subject open, around 2–3 requests a second are steady background load, and it scales with open panes. **Direction:** one SSE "changes" stream from the backend (job and document updates) that the hooks subscribe to. |
| 4.4 | ~~Medium~~ **Fixed 2026-11-03** | **Search loaded every vector on each query.** *Fixed:* `search._vectors` caches each document's matrix and the last few scopes' combined matrix (512 MB cap, least recently used dropped first). SQLite triggers bump `documents.vec_version` on every chunk change, which keeps the cache exact. On a copy of the real library (Methods, 3,009 × 4,096): about 80 ms per question before, 0.3 ms after the first. *Original note:* `search.search` reads and stacks every chunk's BLOB in scope for each question (and `projection.py` does the same for the cloud). A subject with two textbooks has ~4,000 chunks × 2,560 floats ≈ 40 MB of decoding per question, and it grows linearly. **Direction:** cache a per-scope matrix in memory, invalidated by a document `updated_at`, or use `sqlite-vec`. |
| 4.5 | ~~Medium~~ **Fixed 2026-11-03** | **One job worker per lane, strictly FIFO.** *Fixed:* jobs have a priority (jobs panel → **Run next**) and a queue time. A vision job over a long document gives up its lane after 3 minutes when another job waits (at once for a prioritised one), and resumes later from its unfinished pages. Generation can't resume yet, so it doesn't yield. *Original note:* A 900-page vision job blocks every other vision job, including a 3-page upload, for hours. Generation waits behind marking, and so on. There are no priorities and no fairness. (Pausing is new; scheduling hasn't changed.) |
| 4.6 | ~~Low~~ **Fixed 2026-11-03** | **No React error boundary.** *Fixed:* `ErrorBoundary` wraps each page, both sidebars, the centre pane, the chat and the full-screen viewer, with Try again / Close, and logs what happened. *Original note:* An exception in any view (e.g. malformed generated JSON in `ArtifactViewer`) blanks the whole window. Wrap each centre pane and viewer. |
| 4.7 | ~~Low~~ **Fixed 2026-11-03** | **Silent failures.** *Fixed:* `log.py` writes `<data>/logs/backend.log` (rotating). The swallowed exceptions are logged, unhandled API errors are logged with a traceback (the UI gets a short message), and the renderer reports uncaught errors and failed background saves (e.g. annotations) through `POST /client-log` (`src/log.ts`). Maintenance → Open log. Deliberate fallbacks (storage unavailable) stay quiet. *Original note:* 26 empty `catch {}` / `.catch(() => {})` in the front end and 24 broad `except Exception` in the backend** (5 of them `pass`). Some are deliberate (storage unavailable, embedding offline), but failures in places like figure resolution or icon upload vanish without trace. Log them at least (the backend has no logging setup; it uses `print` and `traceback.print_exc`). |
| 4.8 | ~~Low~~ **Fixed 2026-11-03** | `api.ts` types and the backend's rows could drift apart. *Fixed:* `tests/test_api_contract.py` reads the interfaces in `api.ts` and checks real responses contain every required field (subjects, topics, documents, jobs, library, to-dos, pause, maintenance, backups). *Original note:* `api.ts` is one ~400-line client with inline types. It's fine for now, but types for backend rows are written by hand twice (Python dicts and TS interfaces) with nothing checking that they agree. Generating them from FastAPI's OpenAPI schema would catch drift. |
| 4.9 | ~~Low~~ **Fixed 2026-11-03** | Persistence is split. *Fixed:* the per-machine preferences go through one helper (`src/prefs.ts`, which lists every key), and `docs/DATA.md` explains what lives where, what's safe to delete, and how to move to a new PC. *Original note:* Persistence is split between the database (`ui_state`), per-machine `localStorage` (appearance, sidebar widths, chat corner and size, collapsed groups) and `userData` JSON (window chrome and bounds, new). A study pack or a new PC carries none of the UI state. Note this somewhere for the user. |
| 4.10 | ~~Low~~ **Checked 2026-11-03: already fine** | `trash/` and `spike/` sit in the repo root. *Checked:* `trash/` and `spike/samples/` are git-ignored, only eight small spike scripts are tracked, and packaging uses an explicit file list (`dist`, `electron`, `assets`), so neither can reach the app. *Original note:* `spike/samples` holds large real files. Make sure they're git-ignored or moved out, so they don't bloat clones and packaging. |

## 7. Product and UX observations

- **Scope fallbacks were a source of confusing errors** (fixed now: whole-subject scopes use the reference library when topics are empty, and the form names the actual reason). Similar empty-state logic exists in chat (`chat_api._system_prompt`), search and the cloud. Review it with the same "what does the user see when X is empty?" question.
- **Moving files used to re-ingest everything** (fixed: `pipeline.relink`). Deleting a file still doesn't relink the files that depended on it (2.6).
- **Vision runs per document, in upload order**, so a textbook uploaded first delays every later file's vision by hours (4.5). A "run this next" action in the jobs panel would help.
- Generation and marking can't be resumed: cancelling a 20-minute exam job loses everything made so far, because sections are only written at the end.
